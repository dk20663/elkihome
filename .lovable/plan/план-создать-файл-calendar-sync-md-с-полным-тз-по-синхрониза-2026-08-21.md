# Спецификация: двусторонняя синхронизация календаря бронирований с внешними площадками (iCal)

Документ описывает всю логику целиком: модель данных, импорт, экспорт, разрешение конфликтов, расписание и краевые случаи.


## 1. Общая идея

Система — единый источник правды (own database) по занятости двух домов (GREEN, BLACK). Внешние площадки (Авито, Суточно.ру, Циан) обмениваются занятостью только через формат iCal (.ics):

```text
        импорт (pull, раз в 30 мин)
Авито/Суточно/Циан  ── .ics ──►  Edge Function sync-<platform>  ──►  таблица bookings
                                                                        │
Авито/Суточно/Циан  ◄── .ics ──  Edge Function export-ical  ◄───────────┘
        экспорт (площадка сама забирает фид, обычно раз в 1-6 часов)
```

Ключевой принцип: **локальная база главнее фида**. Внешний фид может только добавить занятость, которой у нас нет; он не может переписать или «вернуть» то, что администратор изменил вручную.

## 2. Модель данных

Таблица `bookings` (значимые для синхронизации поля):

| Поле | Назначение |
| --- | --- |
| `house_id` | ссылка на дом |
| `check_in`, `check_out` | даты в формате `YYYY-MM-DD`; `check_out` — исключающая граница (день выезда свободен) |
| `cancelled` | бронь отменена, дата считается свободной |
| `source` | человекочитаемый источник («Авито», «Циан», «Суточно», ручной) |
| `synced_from` | техническая метка канала импорта: `avito` / `sutochno` / `cian` / `null` для ручных |
| `external_uid` | уникальный ключ события площадки: `<platform>_<HOUSE>_<UID из ICS>`; уникальный индекс |
| `manual_override` | администратор вручную вмешался в импортированную бронь (например, отменил её) |
| `guest_name`, `guest_phone`, `comment`, `total_price`, `guest_count`, доп. услуги | заполняются вручную; служат признаком «ручных правок» |

Таблица `houses` хранит адреса входящих фидов: `sutochno_ical_url`, `cian_ical_url`. Для Авито адреса фидов зашиты в коде (можно вынести в такое же поле `avito_ical_url`).

## 3. Импорт (внешние площадки → наша база)

Одна Edge Function на площадку: `sync-avito`, `sync-sutochno`, `sync-cian`. Логика идентичная, различаются только источник URL, префикс `external_uid`, значение `source`/`synced_from` и список «дефолтных» имён гостя.

### 3.1 Парсинг ICS

Текст режется по `BEGIN:VEVENT`; из каждого блока берутся `UID`, `DTSTART`, `DTEND` (формат `YYYYMMDD`, допускается `;VALUE=DATE`), `SUMMARY` (по умолчанию — имя площадки). Событие принимается только при наличии всех трёх: UID, DTSTART, DTEND. Даты нормализуются в `YYYY-MM-DD`.

Пересечение интервалов: `aStart < bEnd && bStart < aEnd` (день выезда не конфликтует с днём заезда).

### 3.2 Алгоритм одного прогона (для каждого дома)

1. Скачать фид. Ошибка сети или код ответа ≠ 200 — залогировать и перейти к следующему дому (никогда не удалять брони по недоступному фиду).
2. Собрать `feedUids` — множество `external_uid` всех событий текущего фида.
3. Загрузить из базы все брони этого дома с `synced_from = <platform>` и непустым `external_uid` (включая отменённые).
4. **Удаление исчезнувших.** Для каждой существующей неотменённой синхронизированной брони, которой нет в `feedUids`:
   - если у брони есть ручные правки (`hasManualEdits`) — не удалять, а ставить `cancelled = true` (данные администратора сохраняются);
   - иначе — удалить строку.
5. Загрузить все активные брони дома (`cancelled = false`, любой источник) — для проверки пересечений.
6. Собрать список «админ освободил»: записи с `cancelled = true AND manual_override = true`.
7. Для каждого события фида:
   - пропустить, если `UID` начинается с `elkihome-` — это наш собственный экспорт вернулся обратно (защита от петли);
   - вычислить `extUid`;
   - если `extUid` уже есть в базе: если запись отменена и **не** `manual_override` — восстановить (`cancelled = false`); иначе ничего не делать; перейти к следующему событию;
   - если интервал пересекается с любой активной бронью — пропустить (та же дата уже занята у нас, дубликат не создаём);
   - если интервал пересекается с «админ освободил» — пропустить (не возвращать даты, которые администратор специально открыл);
   - иначе — вставить новую бронь: `house_id`, даты, `guest_name = SUMMARY`, `source`, `synced_from`, `external_uid`, `total_price = 0`.
   - ошибку вставки с текстом `duplicate`/`unique` игнорировать (гонка параллельных прогонов), остальные логировать.
8. Вернуть JSON со счётчиками: `synced`, `skipped`, `removed`, `cancelled`.

### 3.3 Признак ручных правок (`hasManualEdits`)

Возвращает `true`, если заполнен телефон, комментарий, `total_price ≠ 0`, `guest_count > 1`, включена любая доп. услуга, либо `guest_name` отличается от дефолтных значений площадки (например, для Авито: «авито», «avito», «avito (closed)», «avito (booked)», пустая строка).

## 4. Экспорт (наша база → внешние площадки)

Edge Function `export-ical`, публичный GET, без авторизации (площадки ходят анонимно):

`GET /functions/v1/export-ical?house=GREEN|BLACK`

Правила:

- валидировать параметр `house`, иначе 400; неизвестный дом — 404;
- выбирать **все** активные брони дома (`cancelled = false`), включая импортированные с других площадок — так каждая площадка видит полную занятость;
- **отменённые брони в фид не попадают вообще.** Проверено на практике: Авито блокирует дату при наличии любого `VEVENT`, даже со `STATUS:CANCELLED` и `TRANSP:TRANSPARENT`. «Надгробия» (tombstones) использовать нельзя — дата останется закрытой;
- `UID` события — `elkihome-<booking.id>`, стабилен на всю жизнь брони (позволяет площадкам обновлять, а не дублировать, и служит меткой петли при обратном импорте);
- даты — `DTSTART;VALUE=DATE` / `DTEND;VALUE=DATE` в формате `YYYYMMDD`, без времени;
- заголовки календаря: `VERSION:2.0`, `PRODID`, `CALSCALE:GREGORIAN`, `METHOD:PUBLISH`, `X-WR-CALNAME`, `X-PUBLISHED-TTL:PT15M`, `REFRESH-INTERVAL;VALUE=DURATION:PT15M`;
- поля события: `SUMMARY:Занято`, `STATUS:CONFIRMED`, `TRANSP:OPAQUE`, `SEQUENCE:0`, `LAST-MODIFIED` и `DTSTAMP` = текущий UTC в формате `YYYYMMDDTHHMMSSZ`;
- HTTP-заголовки ответа: `Content-Type: text/calendar; charset=utf-8`, `Cache-Control: no-cache, no-store, must-revalidate`, `Content-Disposition: inline; filename="..."`, плюс CORS.

Ссылки на фиды показываются администратору в настройках с кнопкой «Копировать» — их вставляют в импорт iCal на стороне площадки.

## 5. Расписание

- `sync-avito`, `sync-sutochno`, `sync-cian` — cron `*/30 * * * *` (каждые 30 минут) через `pg_cron` + `pg_net`.
- Экспорт — pull со стороны площадок, обычно раз в 1-6 часов; периодичность мы не контролируем, только подсказываем через `REFRESH-INTERVAL`.
- Все функции — `verify_jwt = false`.

## 6. Разрешение конфликтов (сводная таблица)

| Ситуация | Поведение |
| --- | --- |
| Событие есть в фиде, у нас нет, даты свободны | создать бронь |
| Событие есть в фиде, даты уже заняты у нас | пропустить (наша бронь главнее) |
| Событие исчезло из фида, ручных правок нет | удалить |
| Событие исчезло из фида, есть ручные правки | пометить `cancelled = true`, данные сохранить |
| Событие вернулось в фид, у нас отменено без `manual_override` | восстановить |
| Событие вернулось в фид, у нас `cancelled + manual_override` | игнорировать навсегда (админ освободил дату сознательно) |
| `UID` начинается с `elkihome-` | игнорировать (наш собственный экспорт) |
| Фид недоступен | ничего не менять |

## 7. Защита от петли обратной связи

Три уровня:
1. фильтр по префиксу `UID` `elkihome-` при импорте;
2. проверка пересечения с любыми активными бронями перед вставкой (площадка может пере-экспортировать наше событие уже под своим UID);
3. `manual_override` как «вечный» запрет на повторный импорт освобождённых дат.

## 8. Краевые случаи и требования к реализации

- Импорт должен быть идемпотентным: повторный прогон на неизменном фиде даёт нулевые счётчики.
- Уникальный индекс на `external_uid` обязателен — защищает от гонки параллельных прогонов.
- Все даты — только календарные (`date`), без часовых поясов; сравнение строк `YYYY-MM-DD` лексикографически корректно.
- Никогда не удалять ручные брони (`synced_from IS NULL`) в процессе импорта.
- Логировать каждую ошибку с указанием площадки, дома и `external_uid`.
- При добавлении новой площадки: добавить колонку `<platform>_ical_url` в `houses`, новую функцию `sync-<platform>` по шаблону, свой префикс `external_uid`, свой список дефолтных имён гостя и cron-задачу.
